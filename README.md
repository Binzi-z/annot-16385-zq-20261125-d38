# 隔离区跨代发布的一致性核验

获确认的题面位于 task/PROMPT.txt。使用原生 Windows 和标准库,输入与验证使用本地合成数据。

## 结构

- `gate/core.py` — 发布闸门:追加式提交记录(逐条 fsync)、三段式发布(移动→承诺→回执)、重启恢复
- `gate/model.py` — 独立小模型:纯函数穷举信任代切换时的 108 个可见状态
- `gate/modelcheck.py` — 对拍线束:把每个模型状态在真实闸门上复演比对
- `gate/interleave.py` — 两个真实线程 + 屏障控制的撤销/发布交错,两个崩溃窗口
- `gate/scale.py` — 五万条制品记录的单扫描源撤销触达核验
- `tests/` — 全部规则的 unittest 覆盖
- `run_demo.py` — 端到端演示,审计输出写入 `out/`

## 运行

```
python -m unittest discover -s tests   # 12 个测试
python run_demo.py                     # 生成 out/ 审计输出
```

## 关键不变式

- 提交记录(`commit_log.jsonl`)的 seq 是唯一权威;进程日志顺序不作数
- 两份赞同须引用同一制品摘要与策略版本,且出自不同控制人
- 撤销与发布的竞争由"判定+承诺落盘"的同一把锁序列化,谁先落盘谁生效
- 已移动但承诺未落盘 → 恢复时隔离该文件;承诺已落盘而回执丢失 → 只补回执、返回原承诺,不重新批准
